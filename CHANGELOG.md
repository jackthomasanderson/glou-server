# Changelog

All notable changes to Glou. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Glou uses Calendar Versioning (`YYYY.MM[.PATCH]`, see [CONTRIBUTING.md](CONTRIBUTING.md#versioning)).
Container images are published as `latest` (stable, from `main`), `beta` (from `dev`),
and, on `main`, as the matching `vYYYY.MM[.PATCH]` tag. Changes accumulate under
*Unreleased* until the next promotion of `dev` to `main` cuts a numbered release.
Entries start with the pull request that introduced them where there is one.

## Unreleased

### Removed
- The admin "Access mode" setting (direct or behind a reverse proxy) is gone: it was saved and shown back but changed nothing, only feeding a warning in the network check. The "Check configuration" button still checks the public URL and HTTPS in production (#617).
- The "in-app notifications" channel is gone, from Administration → System configuration → Notifications and from My Profile → Notifications: it was a switch that delivered nothing. Notifications go by email or Gotify. The bell at the top of the page is not affected: it still lists peak-maturity alerts and reminders (#671).

### Changed
- The physical stock count is now called **Stock count** (**Comptage** in French) everywhere, so "Inventory" only names the list of your bottles (#502).
- The tastings page is back at `/tastings`; the old `/cellar-journal` address still works and sends you there from the page itself (no browser redirect, so an old cached link cannot loop) (#502).

### Fixed
- Stopping or updating the API container (`docker compose down`, an image update, a reboot) now lets the API finish the requests in progress and close its database connections, in under a second, instead of waiting 10 seconds and being killed mid-operation: the stop signal now reaches the API (#673).
- The API and web images are now built on exact, recorded versions of their Node.js base image, and the database image in `docker-compose.yml` is pinned the same way, so two builds of the same version ship the same system; updates to these base images arrive as reviewed dependency updates (#610).
- The API no longer stops when the database is unavailable during the nightly cleanup (for example while PostgreSQL restarts for an update at 3 AM): the failure is logged and the next cleanup runs as usual, even when it cannot be recorded in the cleanup history (#634).
- A failed backup is no longer reported to no one on an instance without email or Gotify: while the last backup has failed, or none has succeeded for more than two days while backups are on, administrators see a red banner at the top of every page, with a link to Administration → System configuration → Data. It goes away once a backup succeeds; members never see it (#671).
- Email settings: a new SMTP form now offers **STARTTLS (port 587)**, which works with Gmail and most providers, instead of a "Secure connection (TLS)" switch that failed on that port. The choice names STARTTLS and TLS (implicit, port 465) and moves the port along with it unless you typed your own; instances already configured keep their current setting, with a warning in the card when the port and the security choice do not fit together (for example 587 with TLS). Example texts now start with "e.g." and use example.com (#763).
- Email settings: the test recipient field has its own label, "Test recipient address", and the button reads "Send test" instead of repeating the field name (#764).
- Administration → System configuration → System: the configuration history now says in words what changed, one line per setting with its previous and new value ("Backup time: 03:00 UTC → 04:00 UTC", "New account sign-up: off → on"), instead of a dump of internal field names. Passwords and tokens are never shown: the history only says they were set, changed or removed. Saving a card without changing anything no longer adds an entry. Entries recorded before this version, which kept no previous value, are shown as the values that were saved (#760).
- Administration → System configuration: shortening a retention delay (it deletes older data, audit log entries included, at the next cleanup), turning automatic backups off or keeping their files for fewer days, and opening sign-up now ask for your password, plus your code if you use two-factor authentication. Someone holding a stolen admin session can no longer erase the audit trail, stop the backups or let anyone in. Keeping data longer, turning backups on or closing sign-up need no confirmation (#893).
- Administration → System configuration → Data: the backup time is now chosen from a list, in the server's time zone (shown under the field), like every other scheduled job; it used to be typed in UTC and shifted with daylight saving time. An existing setting is converted once when the API starts, so the backup keeps running at the same time of day as now (#761).
- Administration → System configuration → Data: **Back up now** waits as long as a restore before giving up, and then says the backup is still running on the server instead of reporting a failure. A failed restore is explained in words, never with the raw database error, and restoring a backup whose file was removed says so. Backups deleted by the retention delay disappear from the history. The disaster recovery guide now explains how to restore from the app on a new machine: copy the file into `./backups`, restart the API, then **Restore** (#748).
- Gotify notifications now really go to the Gotify server set up in Administration (URL and application token), for every member who turns Gotify on in their profile; each message's title starts with the member's name, since they all land in the same Gotify application. Members no longer type an address of their own: the field is gone, and addresses saved before are deleted on upgrade. Nothing is sent while Gotify is switched off or misses its URL or token, and it can no longer be switched on without both. A failed profile test now says what went wrong in a sentence instead of a code such as `DELIVERY_FAILED` (#767).

## v2026.11.2 - 2026-11-07

> **Before you update:** v2026.11.1 was never published as a stable release: coming from v2026.11.0, read its section below too, its database change applies. Two-factor secrets are now encrypted with `CONFIG_ENCRYPTION_KEY`: keep your `.env` (and that key) as it is, away from your backups, or your members' authenticator codes stop working. Backups taken before this version still contain those secrets in the clear: delete their copies kept elsewhere (restic, NAS…). Several administrator settings (mail, Gotify, notifications, public URL, backups) now ask for your password, plus a code from your app if your account has two-factor authentication (#890, #613).

### Added
- Two-factor authentication: **Profile → Security & Authentication** now says how many backup codes are left and offers **Generate new codes** (password and a current code asked), which replaces them all: the previous ones stop working at once, and you get the same security notification as when 2FA is turned on or off. The window that shows the codes has a **Copy the codes** button and no longer closes, by Escape or a click outside, before **I've saved my codes** is ticked. A new wiki page, *Lost phone with 2FA on*, explains each way back in, including the database command for an instance whose only administrator is locked out (#638).

### Fixed
- An action that fails now always says so: saving a budget envelope, a maturity reference or a humidor reading, pausing an alert, signing out a session, exporting your data or deleting your account, pausing or resuming a stock count, and other actions that used to fail without a word now show "An error occurred" (or "Cannot reach the server" without network). Actions that already had their own message keep it, without a second one; changes kept on the device while offline are still shown as waiting, not as failed. Creating, editing and deleting a budget envelope now also confirms it, and a failed save keeps its window open with what you typed (#616).
- Profile photos now show on an installed instance: once uploaded, the photo stayed a broken image (or your initial) in the sidebar, the lock screen and the profile, on every device, because it pointed at an address the server does not publish. Photos uploaded before the update are fixed by the update itself (#668).
- In a wine's drawer, each tasting now says which bottle it was as it was when tasted — "Garage · 20 € / bottle · bought Mar 12, 2025" — instead of where the bottle is now: moving the bottle afterwards no longer changes the cellar shown, two tastings of two bottles of the same wine show their purchase days, and a tasting keeps saying which bottle it was once the bottle is finished, in the trash, or its cellar deleted. Tastings noted before this version are shown as before (#837).
- When you add a wine or a cigar, the photo found on the Internet is no longer attached without asking (it was often unrelated: a ball bearing for a cigar). It is now offered under the picture with **Use this photo?**: **Use** attaches it, **Another photo** shows the next one, the cross dismisses it, and the photo stays empty until you choose. Only pictures whose title names the item or its producer are offered, the search says what is looked for (wine bottle, cigar…), and a download that is not a real image is refused instead of being stored as a broken photo (#862).
- An administrator's **Reset password** now also turns the member's two-factor authentication off, as its confirmation says: the member signs in with the temporary password without being asked for a code they can no longer get, and turns 2FA back on from their profile. Every password reset, and every grant of administrator rights, is now confirmed with the administrator's own password, plus a code from their own app if their account has 2FA, so an open admin session alone is no longer enough to reset a password or grant administrator rights; both are recorded in the audit log. An administrator resetting their own password keeps their 2FA (#638).
- Saving the mail server (SMTP), Gotify or the notification channels, sending their tests, saving the public URL, and downloading, restoring or purging the data now ask for the administrator's own password, plus a code from their app if their account has two-factor authentication: someone holding only an open admin session can no longer send password reset links or security alerts to their own server, nor download a backup. Restore and purge still ask for the typed keyword first. Each confirmation, and each refusal, is recorded in the audit log (#890).
- Two-factor secrets are now stored encrypted with the instance's `CONFIG_ENCRYPTION_KEY`, like the SMTP password, so a backup on its own no longer gives the codes of your members' authenticator apps: keep `.env` away from your backups. Secrets saved before are encrypted when the API starts, with nothing to do, and so are those a restored backup brings back. Backups taken before this version still contain them in the clear: delete their copies kept elsewhere (restic, NAS…), or have members turn 2FA off and on again. If you change `CONFIG_ENCRYPTION_KEY`, authenticator codes stop working: members sign in with a backup code and set 2FA up again (wiki *Rotate the secrets*) (#613).
- **Pair with a dish** and the quick search of a stock count no longer offer bottles already drunk, boxes smoked to their last cigar, bottles written off (broken, given away or lost) or in the trash: only what is still in your cellar (#849).
- Analytics: *Estimated appreciation* now compares the estimated value of what is in your cellar with what those same bottles and cigars cost (*Cost of stock*), so drinking a bottle no longer shows as a loss; an opened box counts the share of its cigars left. What you spent overall, bottles drunk, cigars smoked and stock written off included, has its own line under the card. *Consumed* in *Movement flows* counts each bottle drunk and each cigar smoked, no longer one per box finished; with a period chosen, all the cigars smoked from a box count on the day the box was last changed (a cigar smoked, but also a note, a photo or a move) (#838).
- A member can no longer delete another member's profile photo: the profile form no longer sends the photo's address with your names, the address can only be set by uploading a photo, and removing your photo (or a deleted account's) only removes a file that no other account uses (#880).
- Notification webhooks, their **Test** button and the administrator's Gotify test no longer follow redirects: an address that answers with a redirect is reported as a failed delivery, so a webhook can no longer be used to reach machines on the server's own network (#599).
- Deactivating a member now signs them out of every session, forgets their trusted devices and revokes their guest links for good, as the confirmation now says: reactivating the account later no longer brings any of them back. Every activation and deactivation is now recorded in the audit log (#605).

## v2026.11.1 - 2026-11-06

> **Before you update:** this version changes how the cellar plan is stored. The update takes a backup of your database by itself, `./backups/glou-backup-before-migration-<date>.sql.gz`, then transforms your data once, entirely or not at all: every occupied slot is kept, identical lines left apart by the previous update only because each had its slot become one line holding all their slots (single cigars that each had a slot stay apart), and plan coordinates left on a bottle with no cellar, which showed on no plan, are dropped. To go back, restore that backup with the previous image (wiki 31, *Go back*): whatever you entered after the update is lost. On Linux, `mkdir -p backups && sudo chown 1001:1001 backups` first, or the API will not start (#847).

### Added
- Each bottle now has its own slot on the cellar plan: a line of 6 identical bottles can take 6 slots, each box of cigars takes one, and only a group of single cigars still shares one slot with its "×N" badge. **Assign** lists the lines that still have unplaced bottles ("2 placed, 4 unplaced") and says why a line whose bottles are all placed is refused; touching an occupied slot opens the wine on its line ("Slot C2·R3", **Remove from slot**), where **I'm opening one** or **I'm drinking one** takes the bottle of that very slot (an opened bottle keeps it, a drunk one frees it; on the opened bottle's slot, **Finish the opened one** comes first). The drawer says where each line's bottles are ("4 placed, 2 unplaced · C1·R1, C1·R2…"). Glou asks only when it matters: **Which slot?** when you open or drink one bottle of a line with placed bottles, from the drawer or after a tasting's *Update stock?* (*Unplaced* preselected while one is left); **Which slots to free?** when a correction, a write-off or a move leaves a line fewer bottles than slots; **Which slots take the new price?** when the unplaced bottles are not enough for a new price — both on a small numbered plan of the cellar. Bulk *Mark as drunk*, stock counts and guests never ask: an unplaced bottle goes first, otherwise the most recently placed one. Moved bottles arrive unplaced, a line that becomes identical to another one now joins it with its slots, **Undo** puts a bottle back in its slot if it is still free, the history says "Slot C2·R2 taken", "Slot C2·R3 freed" or "Slot C1·R1 → C2·R1", and offline the plan can only be viewed while opening, drinking and correcting still ask which slot (#847).

### Fixed
- Cellar plan: a wine's drawer opened from a slot keeps that slot after **Edit** (closed or saved): **I'm opening one** then takes the bottle of that slot again, instead of asking *Which slot?* with an unplaced bottle preselected. In Analytics, *Category breakdown* names each category in full ("Prestige Cigars" no longer ends in "…"). On a computer, the last field of the add and edit forms (a cigar's *Consumption reminder*, *Single cask*…) no longer sits alone beside an empty half row (#847).
- Analytics: the list under the map (*Results matching the filters*) now shows one row per wine still in your cellar, with how many bottles or cigars are left, instead of one row per bottle including the ones already drunk. The list of cigars no longer scrolls sideways on a computer: columns a cigar never fills (vintage, drinking window) are left out and its stock line breaks only between its parts; in the lists of wines too, the *Region* and *Cellar* columns now show according to the width left to the table (filter panel open or not) rather than the screen's. Long field labels of the add and edit forms ("Consumption reminder", "Alcohol degree (%)"…) no longer run over two lines above or over their value: such a field takes a whole row, together with the short field next to it, so none is left alone beside an empty space. Long tasting titles in the journal are shown whole instead of ending in "…" (#847, #867).
- Clicking the cellar already chosen in **Add bottles** (or any other single-choice menu) no longer empties it: the bottles were saved without a cellar. *No cellar* stays a choice of the list, now in the wish conversion too. On a cellar's page, **Add bottles** offers that cellar rather than the one of the wine's latest line; a line without any slot in a cellar with a plan says "1 unplaced" like the others; **Change the price** no longer says "the unplaced ones are not enough" on a line whose bottles are all placed; **Correct the number** and **Move** no longer move their choices under the cursor when the plan appears; and the **Undo** message no longer covers the drawer's **Remove from slot** (#847).
- A wine's history says what you did in plain words: "1 bottle opened" (the opened bottle keeps its slot, no "slot freed" any more), "1 bottle drunk · Slot C2·R1 freed", "1 cigar smoked", in one line instead of the opened bottle and its line told apart ("Quantity: 6 → 5", "Opened bottle: Yes · Level adjusted to Empty"); entries already recorded read the same way, except the first cigar smoked from a box, which reads "1 box opened", and a whole line moved earlier into an identical one, which does not say the slots it left. A bottle moved to another cellar also says the slot it left ("1 bottle moved to Kitchen · Slot C2·R2 freed"), and **Distribution by cellar** in Analytics now counts the bottles in no cellar under *No cellar*, so it adds up to your stock (#847).

### Changed
- **The update transforms your data once** (#471). Each bottle record becomes a line of a wine: records of the same wine (same category, producer, name and vintage, ignoring case and spaces) are put in one wine when their descriptions do not contradict each other (an empty value is not a disagreement), and strictly identical bottles (same cellar, price, size, purchase date, estimated value, and a purchase place and location that do not contradict each other; none opened, none in a cellar-plan slot or flagged "to check") become one line "x N". Before the update no bottle had a purchase date: for bottles already recorded it is the day you added them to Glou, so bottles entered on different days stay on separate lines, and the budget counts each at that day. Photos and notes that differ do not block the grouping: the most recent photo is kept, the others stay viewable, and notes are put end to end with their dates. A wine bought twice keeps one line per purchase date. Nothing is lost: tastings, history, slots, collections and counts follow, and the update checks its totals (units, value, spending) before and after and cancels itself if anything differs.
- What the update does not settle alone is listed under **To check after the update** (a banner with *View* and *Later*, back at your next sign-in): wines of the same name with contradicting descriptions (**Merge?**, choose field by field, or *It's another wine*), and opened or finished records that counted several bottles, which Glou split as best it could ("Before the update: 3 bottles, opened. Wines you had marked as known but not owned (the "Reference" option of the add form, which no longer exists: a wine tasted elsewhere is now created from "New tasting") become wines "No longer in the cellar" (no bottle), and the rotating-inventory entries that pointed at them are removed.
- The word "asset" is gone from the whole interface: it says wine, bottle, spirit, cigar or reference, and "Enabled / Disabled" for a member account (#471).
- An opened box of cigars is now worth the share of its cigars left (2 smoked out of a box of 25 at 200 € leave 184 €), in the drawer, the cellar cards and the analytics; spending is unchanged. Each line of a wine shows its full purchase date, the cellar map counts the cigars of a box and tells a closed box from an opened one, a bulk move says how many bottles are already in the chosen cellar (and cannot be confirmed when they all are), the trash heads its sections, says how many bottles, boxes or cigars a line holds and restores them in the plural, and an opening undone at once leaves nothing in the history (#471).
