# Changelog

All notable changes to Glou. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

Glou uses Calendar Versioning (`YYYY.MM[.PATCH]`, see [CONTRIBUTING.md](CONTRIBUTING.md#versioning)).
Container images are published as `latest` (stable, from `main`), `beta` (from `dev`),
and, on `main`, as the matching `vYYYY.MM[.PATCH]` tag. Changes accumulate under
*Unreleased* until the next promotion of `dev` to `main` cuts a numbered release.
Entries start with the pull request that introduced them where there is one.

## Unreleased

### Added
- Two-factor authentication: **Profile → Security & Authentication** now says how many backup codes are left and offers **Generate new codes** (password and a current code asked), which replaces them all: the previous ones stop working at once, and you get the same security notification as when 2FA is turned on or off. The window that shows the codes has a **Copy the codes** button and no longer closes, by Escape or a click outside, before **I've saved my codes** is ticked. A new wiki page, *Lost phone with 2FA on*, explains each way back in, including the database command for an instance whose only administrator is locked out (#638).

### Fixed
- An action that fails now always says so: saving a budget envelope, a maturity reference or a humidor reading, pausing an alert, signing out a session, exporting your data or deleting your account, pausing or resuming a stock count, and other actions that used to fail without a word now show "An error occurred" (or "Cannot reach the server" without network). Actions that already had their own message keep it, without a second one; changes kept on the device while offline are still shown as waiting, not as failed. Creating, editing and deleting a budget envelope now also confirms it, and a failed save keeps its window open with what you typed (#616).
- Profile photos now show on an installed instance: once uploaded, the photo stayed a broken image (or your initial) in the sidebar, the lock screen and the profile, on every device, because it pointed at an address the server does not publish. Photos uploaded before the update are fixed by the update itself (#668).
- In a wine's drawer, each tasting now says which bottle it was as it was when tasted — "Garage · 20 € / bottle · bought Mar 12, 2025" — instead of where the bottle is now: moving the bottle afterwards no longer changes the cellar shown, two tastings of two bottles of the same wine show their purchase days, and a tasting keeps saying which bottle it was once the bottle is finished, in the trash, or its cellar deleted. Tastings noted before this version are shown as before (#837).
- When you add a wine or a cigar, the photo found on the Internet is no longer attached without asking (it was often unrelated: a ball bearing for a cigar). It is now offered under the picture with **Use this photo?**: **Use** attaches it, **Another photo** shows the next one, the cross dismisses it, and the photo stays empty until you choose. Only pictures whose title names the item or its producer are offered, the search says what is looked for (wine bottle, cigar…), and a download that is not a real image is refused instead of being stored as a broken photo (#862).
- An administrator's **Reset password** now also turns the member's two-factor authentication off, as its confirmation says: the member signs in with the temporary password without being asked for a code they can no longer get, and turns 2FA back on from their profile. Every password reset, and every grant of administrator rights, is now confirmed with the administrator's own password, plus a code from their own app if their account has 2FA, so an open admin session alone is no longer enough to reset a password or grant administrator rights; both are recorded in the audit log. An administrator resetting their own password keeps their 2FA (#638).
- **Pair with a dish** and the quick search of a stock count no longer offer bottles already drunk, boxes smoked to their last cigar, bottles written off (broken, given away or lost) or in the trash: only what is still in your cellar (#849).
- Analytics: *Estimated appreciation* now compares the estimated value of what is in your cellar with what those same bottles and cigars cost (*Cost of stock*), so drinking a bottle no longer shows as a loss; an opened box counts the share of its cigars left. What you spent overall, bottles drunk, cigars smoked and stock written off included, has its own line under the card. *Consumed* in *Movement flows* counts each bottle drunk and each cigar smoked, no longer one per box finished; with a period chosen, the cigars smoked from a box are dated by its last smoke (#838).

## v2026.11.1 - 2026-11-06

> **Before you update:** this version changes how the cellar plan is stored. The update takes a backup of your database by itself, `./backups/glou-backup-before-migration-<date>.sql.gz`, then transforms your data once, entirely or not at all: every occupied slot is kept, identical lines left apart by the previous update only because each had its slot become one line holding all their slots (single cigars that each had a slot stay apart), and plan coordinates left on a bottle with no cellar, which showed on no plan, are dropped. To go back, restore that backup with the previous image (wiki 31, *Go back*): whatever you entered after the update is lost. On Linux, `mkdir -p backups && sudo chown 1001:1001 backups` first, or the API will not start (#847).

### Added
- Each bottle now has its own slot on the cellar plan: a line of 6 identical bottles can take 6 slots, each box of cigars takes one, and only a group of single cigars still shares one slot with its "×N" badge. **Assign** lists the lines that still have unplaced bottles ("2 placed, 4 unplaced") and says why a line whose bottles are all placed is refused; touching an occupied slot opens the wine on its line ("Slot C2·R3", **Remove from slot**), where **I'm opening one** or **I'm drinking one** takes the bottle of that very slot (an opened bottle keeps it, a drunk one frees it; on the opened bottle's slot, **Finish the opened one** comes first). The drawer says where each line's bottles are ("4 placed, 2 unplaced · C1·R1, C1·R2…"). Glou asks only when it matters: **Which slot?** when you open or drink one bottle of a line with placed bottles, from the drawer or after a tasting's *Update stock?* (*Unplaced* preselected while one is left); **Which slots to free?** when a correction, a write-off or a move leaves a line fewer bottles than slots; **Which slots take the new price?** when the unplaced bottles are not enough for a new price — both on a small numbered plan of the cellar. Bulk *Mark as drunk*, stock counts and guests never ask: an unplaced bottle goes first, otherwise the most recently placed one. Moved bottles arrive unplaced, a line that becomes identical to another one now joins it with its slots, **Undo** puts a bottle back in its slot if it is still free, the history says "Slot C2·R2 taken", "Slot C2·R3 freed" or "Slot C1·R1 → C2·R1", and offline the plan can only be viewed while opening, drinking and correcting still ask which slot (#847).

### Fixed
- Cellar plan: a wine's drawer opened from a slot keeps that slot after **Edit** (closed or saved): **I'm opening one** then takes the bottle of that slot again, instead of asking *Which slot?* with an unplaced bottle preselected. In Analytics, *Category breakdown* names each category in full ("Prestige Cigars" no longer ends in "…"). On a computer, the last field of the add and edit forms (a cigar's *Consumption reminder*, *Single cask*…) no longer sits alone beside an empty half row (#847).
- Analytics: the list under the map (*Results matching the filters*) now shows one row per wine still in your cellar, with how many bottles or cigars are left, instead of one row per bottle including the ones already drunk. The list of cigars no longer scrolls sideways on a computer: columns a cigar never fills (vintage, drinking window) are left out and its stock line breaks only between its parts; in the lists of wines too, the *Region* and *Cellar* columns now show according to the width left to the table (filter panel open or not) rather than the screen's. Long field labels of the add and edit forms ("Consumption reminder", "Alcohol degree (%)"…) no longer run over two lines above or over their value: such a field takes a whole row, together with the short field next to it, so none is left alone beside an empty space. Long tasting titles in the journal are shown whole instead of ending in "…" (#847, #867).
- Clicking the cellar already chosen in **Add bottles** (or any other single-choice menu) no longer empties it: the bottles were saved without a cellar. *No cellar* stays a choice of the list, now in the wish conversion too. On a cellar's page, **Add bottles** offers that cellar rather than the one of the wine's latest line; a line without any slot in a cellar with a plan says "1 unplaced" like the others; **Change the price** no longer says "the unplaced ones are not enough" on a line whose bottles are all placed; **Correct the number** and **Move** no longer move their choices under the cursor when the plan appears; and the **Undo** message no longer covers the drawer's **Remove from slot** (#847).
- A wine's history says what you did in plain words: "1 bottle opened" (the opened bottle keeps its slot, no "slot freed" any more), "1 bottle drunk · Slot C2·R1 freed", "1 cigar smoked", in one line instead of the opened bottle and its line told apart ("Quantity: 6 → 5", "Opened bottle: Yes · Level adjusted to Empty"); entries already recorded read the same way, except the first cigar smoked from a box, which reads "1 box opened", and a whole line moved earlier into an identical one, which does not say the slots it left. A bottle moved to another cellar also says the slot it left ("1 bottle moved to Kitchen · Slot C2·R2 freed"), and **Distribution by cellar** in Analytics now counts the bottles in no cellar under *No cellar*, so it adds up to your stock (#847).
- The browser tab now always shows the page you are on (a cellar's name, *Cellars*, *Sign in*…): about one load in two it stayed on "Glou" (#863).
- **Undo** right after opening, drinking or smoking one bottle or cigar of a line now leaves nothing in the wine's history, also from a slot of the plan and for a guest: "Quantity: 2 → 3" was left behind (#847).
- Cellar plan: an opened bottle or box is now hatched, with an "Opened" entry in the legend, so it no longer looks like a full one; and a cell's tooltip opens beside the cell instead of covering the counter or the row above (#847).
- Cellar plan: a bottle dragged with the mouse lands in the slot it is released on, no longer one slot further when the gesture is quick. A slot's tooltip no longer gets in the way: a hover or a click on the slots it covers reaches them, it closes as soon as the pointer leaves its slot and no longer shows while a bottle is dragged; an opened bottle and an opened box share one *Opened* entry in the legend (#847).
- The first click after closing a drawer or a window is no longer lost: a slot of the plan, a view switch or a link of the side menu clicked while the drawer or window was still sliding away did nothing. A message next to a wine's drawer now leaves downwards instead of sliding over the drawer's **Add bottles** and **Edit**, and a message on its way out no longer catches a click (#847).
- Cellar plan: a bottle dragged with the mouse or a finger now lands in the slot under the pointer when it is released, even when the gesture ends quickly or without a last move. It no longer lands in the slot it passed over just before, where it silently swapped places with the bottle there, and a release off the plan moves nothing (#847).
- With a wine's drawer open on a computer, the **Undo** message now shows at the bottom, next to the drawer, instead of over the side menu and the page's back arrow; a single-choice list closes again when you click the choice already made; the cellar type filter shows whole names ("Wine Cooler / Service"); a cigar's recommended humidity, the alcohol degree and the cask strength no longer read "(%)%"; **Correct the number** loses the empty space above **Which slots to free?**; and **Edit this line** names its free-text field "Free note (shelf, crate…)", so it is not mistaken for a slot of the plan (#847).
- Cigars: **Undo** right after *I'm smoking one* from a full box now leaves nothing in its history, as for wines: "Bottle opened: No · Cigars Left: 25" was left behind (the same after undoing the opening of a single bottle, and for a guest). The history names every field in plain words, a box's own ("Box opened", "Cigars left"), and editing a cigar or a spirit says "Cigar updated" or "Spirit updated", not "Wine updated" (#847).

## v2026.11.0 - 2026-11-05

> **Before you update:** this version changes how your cellar is stored (see *Changed* below). The update takes a backup of your database by itself, `./backups/glou-backup-before-migration-<date>.sql.gz`, then transforms your data once. To go back, restore that backup with the previous image (wiki 31, *Go back*): whatever you entered after the update is lost. On Linux, `mkdir -p backups && sudo chown 1001:1001 backups` first, or the API will not start. After the update, open **To check after the update** (banner on the wine list) to settle what Glou could not decide alone (#471).

### Added
- A wine is now one card for all its identical bottles (#471). Adding a wine asks **Number of bottles**; the card reads "5 full · 1 opened (60 %)", and its drawer lists one line per cellar, price, size and purchase date. **Add bottles** on a wine adds more (same purchase date joins the line, another date makes a new line), and **Correct the number** only goes down, with its reason: *Input error* (the bottles never existed, spending included) or *Broken, given away or lost* (they leave the cellar and its value but stay in your spending). The same goes for spirits, sparkling wines and cigars.
- Counters count bottles and cigars, not records: "142 bottles · 58 wines" on the Wines page, "23 bottles · 17 spirits", "89 cigars · 12 references", and "2 here · 9 in all" when you filter by cellar. Value, spending, budget, alerts and the cellar plan follow (#471).
- Cigars in closed boxes and single cigars: add "N boxes of M cigars" or "N single cigars", with the price of one box or one cigar. Smoking the first cigar of a closed box opens it ("opened box, M-1 left"); a smoked single cigar stays in your history and spending like a drunk bottle (#471).
- **I'm opening one / I'm drinking one / I'm smoking one** on a wine (*I'm drinking one* is a secondary button next to the main one): only one bottle leaves its line, and when several lines could serve Glou asks **Which bottles?**, preselecting the cellar you are looking at, then the oldest purchase. **Undo** stays for 8 seconds. An opened bottle put back to full with **Undo the opening** (or its level set back to full) rejoins the identical line, and Glou asks whether to keep a tasting noted on it (#471).
- When a bottle is already opened, opening another reminds you ("A bottle is already opened (60 %)": *Finish the opened one* or *Open a new one*), marking one as drunk asks "Is it the one you finished?", and the consumption plan suggests finishing the opened one first. For cigars with an opened box and closed boxes, Glou asks which to smoke from (#471).
- **You already have this wine** when you type a wine you hold (form, label scan, wish conversion, first-run wizard): only the number, cellar and price remain to enter, and *It's another wine* remembers that the two are different. The old duplicate warning with *Increment quantity* is gone (#471).
- A wine you no longer hold stays known: tastings, history and a one-click **Add bottles** remain. It is hidden from the list by default, found with the **No longer in the cellar** filter and the search, and a wine tasted elsewhere is created without a bottle from **New tasting** (#471).
- **Move** and **Change the price** apply to part of a line ("How many to move?", "For how many bottles?") and split the line; a line made identical to another one joins it (#471).
- CSV import by groups: a `quantity` of 6 makes a line of 6, identical rows add up, a wine already in the cellar is flagged with *Add these N bottles* or *Ignore (already counted)* (ignore by default), an unknown cellar is created and announced, dates are read day first (`15/03/2024` or `2024-03-15`), and the limit is now 500 rows, not 500 bottles. New columns are read: cellar, purchase date, bottle size, vitola, cigars per box, opened, level, and the wine's description (#471).
- **Export my cellar (CSV)** in Profile → Data & Privacy: one line per line of the cellar plus one per opened bottle or box, with the wine's description, that the import reads back as is (French headers and `;` in French, English headers and `,` in English). Photos, tastings, history, alerts, cellar-plan slots and drunk or trashed bottles are only in the JSON export (#471).
- Rotating inventory counts a line with one answer ("How many did you find?"): missing bottles are marked drunk or corrected with their reason, extra ones added to the line, and a find of 6 bottles makes a line of 6 (#471).
- Tastings belong to the wine: all of them show on its card whatever the bottle, a tasting can be noted with no bottle ("No, tasted elsewhere", also for a wine Glou did not know yet), and a tasting follows the bottle it was noted on when that bottle is opened or put back (#471).
- Offline, you can open, drink or smoke one bottle and correct a number: the action shows at once as "waiting for the connection" and is sent when the network is back, with the existing conflict window if the line changed meanwhile. Adding, moving, repricing and merging still need the network (#471).
- Guests with a read/write link can open, drink or smoke one bottle of a line (*I'm drinking one* finishes the opened bottle first, as for members), **Undo** it during 8 seconds, and note a tasting on the bottle they just finished (from its message, the reminder on the page or the wine's card), signed "Name (guest)" and dated today; the page keeps offering that tasting after the message is gone. They cannot change a number, move or add, close an opened bottle again, or edit the wine's notes. When creating a share, the switch next to each cellar now reads **Allow opening, drinking or smoking** (#471).
- Bulk actions on wines: **Move**, **Mark as drunk** (asks how many for each wine with several bottles) and **Move to trash** apply to every bottle in the cellar of the selected wines, with a summary first. Bulk-action templates that wrote a state (opened, level, opening date) are removed by the update (#471).
- A wine's description (name, region, grapes, notes…) is edited once for all its bottles from its drawer, and a value can be restored from the wine's history (#471).
- Before applying a database migration, an update now backs the database up automatically into `./backups/glou-backup-before-migration-<date>.sql.gz`. That file is never deleted by retention: it is the only way back to the previous version, so delete it yourself once you trust the update. If the backup cannot be taken, nothing is migrated and the API does not start; if a migration fails and the API restarts in a loop, the backup already taken is reused instead of a new one each time (#754).
- **On Linux, before your next update:** run `mkdir -p backups && sudo chown 1001:1001 backups` in your Glou folder. Without it the automatic backup cannot be written and the API no longer starts after an update that brings a migration (#754).

### Changed
- **The update transforms your data once** (#471). Each bottle record becomes a line of a wine: records of the same wine (same category, producer, name and vintage, ignoring case and spaces) are put in one wine when their descriptions do not contradict each other (an empty value is not a disagreement), and strictly identical bottles (same cellar, price, size, purchase date, estimated value, and a purchase place and location that do not contradict each other; none opened, none in a cellar-plan slot or flagged "to check") become one line "x N". Before the update no bottle had a purchase date: for bottles already recorded it is the day you added them to Glou, so bottles entered on different days stay on separate lines, and the budget counts each at that day. Photos and notes that differ do not block the grouping: the most recent photo is kept, the others stay viewable, and notes are put end to end with their dates. A wine bought twice keeps one line per purchase date. Nothing is lost: tastings, history, slots, collections and counts follow, and the update checks its totals (units, value, spending) before and after and cancels itself if anything differs.
- What the update does not settle alone is listed under **To check after the update** (a banner with *View* and *Later*, back at your next sign-in): wines of the same name with contradicting descriptions (**Merge?**, choose field by field, or *It's another wine*), and opened or finished records that counted several bottles, which Glou split as best it could ("Before the update: 3 bottles, opened. Glou counted 1 opened + 2 full"; **That's right** or **Correct the number**). A quantity above 1 typed with the old *Increment quantity* button is kept and now counts.
- Cigar records become boxes holding the number of cigars they had left (closed, or opened if the record was opened; an emptied record becomes a finished box). Wines you had marked as known but not owned (the "Reference" option of the add form, which no longer exists: a wine tasted elsewhere is now created from "New tasting") become wines "No longer in the cellar" (no bottle), and the rotating-inventory entries that pointed at them are removed.
- The word "asset" is gone from the whole interface: it says wine, bottle, spirit, cigar or reference, and "Enabled / Disabled" for a member account (#471).
- An opened box of cigars is now worth the share of its cigars left (2 smoked out of a box of 25 at 200 € leave 184 €), in the drawer, the cellar cards and the analytics; spending is unchanged. Each line of a wine shows its full purchase date, the cellar map counts the cigars of a box and tells a closed box from an opened one, a bulk move says how many bottles are already in the chosen cellar (and cannot be confirmed when they all are), the trash heads its sections, says how many bottles, boxes or cigars a line holds and restores them in the plural, and an opening undone at once leaves nothing in the history (#471).
- Restoring a backup made by another version of Glou is now refused with a message that points to the right procedure, instead of leaving a database the running version cannot read (#471).
- A guest can no longer put an opened bottle back to full or edit a wine's notes, which now belong to the wine (#471).

### Security
- Dependencies updated for published security advisories: `multer` 2.5.0 (photo uploads), `nodemailer` 10.3.1 (emails), and `body-parser`, `qs`, `ip-address`, `fast-uri`, `seroval`, `serialize-javascript` and the test tool `vitest` to their fixed versions (#755).

### Fixed
- Offline changes sync reliably. Two changes to the same bottle made without network (opened at 50 %, then finished) no longer end in a conflict with yourself; each is still sent on its own. Changes sent while the server restarts stay pending and go through on their own a few seconds later instead of being marked refused. The conflict window lists only the fields that differ, with their names and the cellar name, and *Decide later* is remembered when you change page. In the list view, the pending-sync clock, the cellar name and the category follow edits, cellar renames and language switches without a reload (#585, #738).
- Moving a bottle to another cellar (edit form, *Move to a cellar* bulk action, or an inventory count) now leaves it unplaced in the new cellar instead of keeping its old grid position there. Before, it could silently take a slot nobody had chosen, or the move was refused because that slot was already taken (#799, #798).
- The quick start on the project website now has the Linux step that lets nightly backups work (`mkdir -p backups && sudo chown 1001:1001 backups`), and its update line asks for a backup first. If you installed from the website on Linux, run `sudo chown 1001:1001 backups` in your Glou folder before your next update (#752, #667).
- After an update, an open page no longer shows raw text keys or old labels until you reload it: translations are fetched again whenever they change, and stay available offline. Shares in Profile show their status (*Active*, *Expired*, *Revoked*), the state filter of the Analytics map has its labels, browser tabs are titled in your language only, and cigars no longer read wine wording (tastings in the drawer, *Restore the box* with its count in the trash, assigning a slot on the cellar plan, which names bottles, boxes and cigars in a cellar holding both). Messages now appear just below the top edge, so they no longer cover the close button of a drawer, and deleting a cellar names it (#471).

## v2026.10.3 - 2026-10-30

### Added
- Advanced setting `API_RATE_LIMIT_MAX` in `.env`: how many requests one address may send every 15 minutes (1000 by default), to raise if many devices share one address and get *Too many requests*. The sign-in and password-reset limits do not change (#746).

### Security
- Another app hosted under the same domain (for example `photos.home.example` next to `glou.home.example`) can no longer send requests to Glou on behalf of a signed-in member. Its address must be listed in `APP_URL`, `CORS_ORIGIN` or `CSRF_TRUSTED_ORIGINS` (#740, #600).
- Guest share links no longer appear in clear text in the error and rejected-request lines of the `api` log (#740, #612).
- A crafted sign-in link can no longer send you to another website once signed in; the page you asked for, query string and anchor included, is still restored after sign-in and after the two-factor step (#740, #602).

### Fixed
- Running the web app from a source checkout (`npm run dev` or a local build) showed it with two thirds of the interface library's styles missing: fields without borders, square buttons with dark text, no keyboard focus ring, dialogs not full-screen on a phone. Published images were not affected (#722, #721).
- Select menus no longer flash about a third of a second after opening (#723, #709).
- Form windows no longer jump while you fill them in. Opening a section, a field that appears, a password strength gauge or an error message used to re-centre the whole window and move every field, sometimes under the pointer. Forms that change height as you fill them (bottle, cellar, tasting, wish, collection, share link, bulk action, maturity reference, password and PIN) now stay anchored at the top on a computer, and the longer ones scroll inside their window (#723, #709).
- A tasting without stars can now be saved. Saving one, removing the stars of a rated tasting, or saving with the date field cleared failed with "Failed to save the tasting" (#724, #704).
- Emptying a field of an existing bottle now clears it. Emptying the vintage (to make it non-vintage), a price, the alcohol degree or the colour saved without error and kept the old value; emptying the opening or reminder date made the save fail. A disgorging or cask date typed then cleared when adding a bottle was saved as 1 January 1970 (#727, #726).
- The bottle form no longer rewrites what you type. A price such as 24.05 used to turn into 245, because a 0 right after the decimal separator was dropped, and 24.90 into 24.9. Grape varieties typed as "Pinot Noir, Gamay" lost their spaces and commas. Prices and degrees take a comma or a dot whatever the browser language: a browser set to English silently dropped the comma, turning 24,05 into 2405. The same fix applies to the wish form, whose quantity also could not be emptied to type over it. The cellar field shows *No cellar* instead of a blank when no cellar is chosen, and the service temperature field shows an example (#725, #706).
- A peak window that ends before it starts (2035 to 2028) is refused, under the field and by the server, instead of being saved and skewing the peak alerts (#725, #706).
- The automatic bottle photo now follows the name you end up typing. A pause while typing used to attach the photo found for a half-typed name for good. A photo you choose yourself is never replaced (#725, #706).
- With every section open, the tasting window spilled out of its panel and its Cancel and Save buttons were drawn below it, on the dark backdrop. It now scrolls inside its panel and keeps its buttons in view (#723, #704).
- On a phone, the last six windows that still opened as a small box now open full-screen like the others: wish price, conversion and deletion, the stock question after a tasting, cellar deletion and the list of changes waiting to be sent (#723, #654).
- Food pairing now suggests the red and white wines in your cellar: "Viande" or "agneau" used to find nothing, and only rosé and orange wines ever came up. A white wine now gets white-wine serving advice instead of a red's (16–18 °C, aeration, lamb), and a wine without a colour gets none rather than a wrong one (#731, #703).
- On a phone, the first-run wizard scrolls and fills the screen. When a step was taller than the screen, such as the preview of a cellar file, its top and bottom were cut off with no way to reach them: *Confirm import*, *Back*, *Skip this step* or *Later* could not be pressed. Each step now opens at its top. On a narrow phone, the cellar step's buttons ran past the edge of the card and cut *Create cellar* off; they now wrap onto two lines. On a computer, a window too short for the wizard now scrolls too (#730, #686).
- Editing a tasting now shows its perceived maturity and, in expert mode, its tasting grid (appearance, nose, palate, tannin, acidity, finish), which used to appear empty. Saving a tasting without touching it no longer erases its perceived maturity, and what you type in the tasting window is no longer wiped when the page refreshes its data in the background (#736, #642).
- After a tasting, the stock question no longer puts an already opened bottle back to 50 % with today as its opening date: for an opened bottle it only offers to mark it empty (#736, #595).
- After a cigar tasting, the stock question offers to remove one cigar from the box instead of marking the whole box empty (#736, #586).
- Backups restore again with the disaster-recovery and rollback procedures of the wiki: every backup stopped them near its start, on a setting the PostgreSQL 15 database Glou ships rejects, and nothing was restored. New backups no longer contain that setting, and the documented command now also restores older ones. The disaster-recovery page now sends you to the `./backups` folder instead of an old Docker volume that only holds backups from before 2026.10 (#737, #665).
- A backup is recorded as successful only once its file is completely written. A disk that filled up during the last moments of a backup left a truncated file marked successful, and older good backups could then be deleted by the retention (#737, #670).
- The Backups tab now warns when Glou cannot write to its backups folder. If the check itself fails, the tab says so instead of staying silent (#737, #669).
- Peak and humidor alerts are no longer lost in night-time quiet hours. They were sent at 3 a.m. and a message that falls in your quiet hours is dropped, not delayed, so a 22:00 → 07:00 range swallowed every one of them. They are now sent at 10:00. Quiet hours, and the times of the daily jobs, are now read in the instance's time zone instead of UTC. It is `Europe/Paris` unless you set another one with `TZ` in `.env`; an existing `docker-compose.yml` also needs the `TZ` line of the new one for that setting to apply. The setting now says what happens to a message during quiet hours (#741, #575).
- Turning off one notification category no longer turns off all the others. From the default (every category on), unticking one used to leave it as the only one on, peak alerts included. Lists saved that way are left as they are: check your categories in your profile (#741, #583).
- A deactivated or deleted account no longer receives the household's humidor alerts, nor any other notification (#741, #591).
- Saving a bottle no longer overwrites what someone else changed while your form was open: it now says the bottle was changed in the meantime and saves nothing, so you can reopen it and start from the latest version. Saving also only touches the fields you changed, so correcting a price no longer removes the scan and import badges of the other fields or marks them as set by hand (#735, #572).
- A bottle's name can be corrected when editing it. The field was greyed out, so a typo or a misread label could only be fixed by deleting and recreating the bottle (#735, #643).
- Bottles can be selected in list view: selection mode showed no checkboxes there and a click on a row selected nothing. Cancelling a bulk action and then leaving selection mode no longer replaces the page with an error, and the bulk action window now opens with no field ticked each time (#732, #705).
- Glou no longer crashes in a browser set to block site data (Chrome "Sites can't save data", Firefox "block all cookies"): even the sign-in page used to fail with a bare "Application error". Preferences such as the language or the quick lock are simply not remembered there (#734, #584).
- When the database restarts (after an update, for instance), members are no longer sent back to the sign-in screen as if their session had expired; opening the app meanwhile shows "Cannot reach the server" with a retry button (#734, #581).
- Restoring a backup from the Backups tab now first takes a backup of the current data, which stays in the history so a wrong restore can be undone; if that backup fails, nothing is restored. After a restore, the history still lists every backup, including those newer than the restored one, and a backup file copied by hand into the `./backups` folder appears in it after a restart (#745, #666).
- On the lock screen, a wrong password or PIN now says "Incorrect password or PIN code." and empties the field, ready for another try. It used to show nothing, so the app looked frozen. Too many attempts, a server that cannot be reached and a session that has ended get their own message. Only wrong codes count towards the limit of attempts: a tablet unlocked often during the day is no longer blocked (#744, #582).
- After too many sign-in, two-factor, password-reset or unlock attempts, the screen now says how many minutes to wait instead of "An unexpected error occurred" or "An error occurred. Try again.", which only prolonged the block. A password-reset link checked while the server cannot be reached offers to try again instead of calling the link invalid or expired (#744, #640).
- Turning two-factor sign-in on or off in the profile shows a sentence in your language, such as "Incorrect verification code.", instead of codes like "INVALID_TOTP_CODE". The code fields there, and in "Trust this device", open the number keypad on a phone; a button switches to the full keyboard for a backup code (#744, #652).
- Deleting a cellar no longer says it failed when it worked: the confirmation closes and the cellar leaves the list. A deleted bulk-action preset now leaves the list straight away instead of staying until the page is reloaded, and a preset that cannot be deleted says so. Removing a bottle from a collection, or adding it to one, now says when it fails instead of passing it off as done; a save touching several collections shows a single message (#743, #580).
- A bottle photo that cannot be sent now says why: too large (5 MB at most), unsupported format, image address that cannot be downloaded, or a connection problem. An upload that hangs gives up after a minute, so the loading spinner no longer stays on the photo forever, and the previous photo is kept. AVIF photos can be chosen from the device too (#743, #645).
