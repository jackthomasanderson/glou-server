# Configure the Public URL & Network Access Mode

## TL;DR
Tell Glou the address people use to reach your instance from outside, so links and shares generated by the app are correct — and run a quick consistency check before you trust it.

## Prerequisites
* Admin account.
* Know the exact public address of your instance (e.g. `https://cave.example.com`), if you have one.

## Action

### Set the public URL and access mode
1. Go to **Admin → System Configuration → Network**.
2. Fill in **Public URL** with the address your instance is reachable at from outside (e.g. `https://cave.example.com`). Leave it empty to fall back to the `APP_URL` environment variable, or `http://localhost:3000` if that variable isn't set either.
3. Set **Access mode**:
   - **Direct** — the instance is reached directly.
   - **Reverse proxy** — the instance sits behind a reverse proxy (Nginx, Traefik, Caddy, etc.).
4. Click **Save**. The panel shows the **effective URL** actually in use (your configured value, or the `APP_URL` fallback if you left the field empty).

### Run the consistency check
1. Click **Verify consistency**.
2. The check is purely local — it does not make any outbound network call, so it won't fail because of DNS or because the proxy isn't live yet. It verifies:
   - The effective URL is syntactically valid.
   - In production (`NODE_ENV=production`), the URL uses `https://` — otherwise you get a `NOT_HTTPS_IN_PRODUCTION` warning.
   - If **Access mode** is set to **Reverse proxy** but the effective URL still points to `localhost`/`127.0.0.1`, you get a `PROXY_MODE_LOCALHOST_URL` warning.
3. Read the result: warnings are advisory, not blocking — the check only reports `ok: false` when the URL itself is invalid.

> [!TIP]
> **Access mode** is informational: it drives the consistency check and is shown as a status chip in the admin panel, but it does not configure Express's `trust proxy` setting or any other server-side proxy behavior. If your reverse proxy needs specific headers forwarded, configure that at the proxy/deployment level, not through this toggle.

## The Firewall (Troubleshooting)

| Error / Behavior | Fix |
| :--- | :--- |
| **`NOT_HTTPS_IN_PRODUCTION` warning** | Your effective URL uses `http://` while `NODE_ENV=production`. Set **Public URL** to an `https://` address, or fix your TLS termination at the proxy. |
| **`PROXY_MODE_LOCALHOST_URL` warning** | Access mode is **Reverse proxy** but the effective URL still resolves to localhost. Set **Public URL** to the real external address the proxy exposes. |
| **Links generated by the app still point to the wrong address** | Confirm you clicked **Save** after entering the Public URL, and re-check the **effective URL** shown in the panel — an empty field silently falls back to `APP_URL`/`localhost`. |
| **I don't have a Public URL configured — is that a problem?** | Not for local/single-user use. Without one, Glou falls back to `APP_URL` (set in your `docker-compose.yml`) or `http://localhost:3000`. Only set a Public URL if the instance is reachable from outside and you want links to reflect that. |
